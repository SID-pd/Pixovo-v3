# Stage 1.3 — Storage offload

**Milestone 1 · 2 days · Depends on [1.1](M1-1.1-session-continuity.md)**

---

## 1. Objective

Get full-resolution originals off the ingest path and onto a demand-driven background stream, behind a storage interface that swaps to S3 later without touching any caller. Today originals are uploaded twice, and uploading them all eagerly does not fit on a local disk at the 20 × 1,000 target.

---

## 2. Current state

### 2.1 Originals are uploaded twice

**Path 1 — inside ingest.** [`client_downsampler.js:162`](../../frontend/src/utils/client_downsampler.js) appends every original to the ingest `FormData`; [`main.py:176`](../../backend/app/main.py) writes them all to disk in the request handler.

**Path 2 — background sync.** [`App.jsx:70`](../../frontend/src/App.jsx) `streamOriginalsInBackground()` then POSTs *the same files again* to `/api/upload-originals`, 3 at a time.

Every original crosses the network twice and is written to disk twice, under two different paths (see §2.3).

### 2.2 Eager upload does not fit

| Strategy | Photos/user | 1 user | 20 users |
|---|---|---|---|
| Eager — every original | 1,000 | ~8 GB | **~160 GB** |
| Survivors only | ~600 | ~4.8 GB | ~96 GB |
| **Placed photos only** | ~250 | ~2 GB | **~40 GB** |
| Thumbnails (always) | 1,000 | 30 MB | 600 MB |

Only photos that (a) survive filtering **and** (b) are placed in a spread ever reach the PDF. Uploading the rest is pure waste — on local disk today and on S3 egress later.

### 2.3 The two write paths disagree

| Writer | Path |
|---|---|
| Ingest ([`main.py:181`](../../backend/app/main.py)) | `/uploads/originals/{session_id}/{photo_id}_orig_{filename}` |
| `/api/upload-originals` ([`main.py:672`](../../backend/app/main.py)) | `/uploads/originals/{photo_id}_orig{ext}` — **flat, no session** |

`mark_original_synced()` overwrites the session-scoped `original_url` with the flat one, so `pdf_exporter` may look in the wrong place. Stage 1.1 Task 8 fixes the path; this stage removes the duplicate write.

### 2.4 Whole files are buffered in memory

[`main.py:666`](../../backend/app/main.py): `content = await file.read()` loads an entire 20 MB original into RAM before writing. At 20 concurrent uploads that is 400 MB of avoidable transient memory.

### 2.5 No storage abstraction

`UPLOADS_ORIGINALS_DIR` and friends are referenced directly across `main.py`, `pdf_exporter.py`, and `config.py`. Every one is a future S3 migration site.

---

## 3. Target state

- Ingest carries thumbnails + metadata only (done in 1.1); originals never appear in it.
- Originals stream in the background, **prioritised by placement order**, only for survivors.
- All file I/O goes through a `StorageBackend` interface with a `LocalDiskBackend` implementation.
- Uploads stream to disk rather than buffering in memory.
- A disk watermark rejects new sessions before the volume fills.

---

## 4. Tasks

### Task 1 — The `StorageBackend` interface

New file `backend/app/storage/base.py`:

```python
from abc import ABC, abstractmethod
from typing import BinaryIO, Optional

class StorageBackend(ABC):
    """Abstracts where photo bytes live. LocalDisk today, S3 later."""

    @abstractmethod
    def put_stream(self, key: str, stream: BinaryIO, content_type: str = "image/jpeg") -> str:
        """Write a stream to `key`. Returns the public URL."""

    @abstractmethod
    def get_path(self, key: str) -> Optional[str]:
        """Local filesystem path for reading. For S3, downloads to a temp file."""

    @abstractmethod
    def url_for(self, key: str) -> str:
        """Public/browser-facing URL for `key`."""

    @abstractmethod
    def exists(self, key: str) -> bool: ...

    @abstractmethod
    def delete(self, key: str) -> None: ...

    @abstractmethod
    def delete_prefix(self, prefix: str) -> int:
        """Delete everything under a prefix. Returns count. Used by retention."""

    @abstractmethod
    def total_bytes(self, prefix: str = "") -> int: ...
```

`backend/app/storage/local.py`:

```python
import shutil
from pathlib import Path
from app.storage.base import StorageBackend

class LocalDiskBackend(StorageBackend):
    def __init__(self, root: Path, url_prefix: str = "/uploads"):
        self.root, self.url_prefix = Path(root), url_prefix

    def _p(self, key: str) -> Path:
        # keys are "originals/{session_id}/{photo_id}.jpg" — never absolute, never traversing
        safe = Path(key)
        if safe.is_absolute() or ".." in safe.parts:
            raise ValueError(f"Unsafe storage key: {key}")
        return self.root / safe

    def put_stream(self, key, stream, content_type="image/jpeg") -> str:
        path = self._p(key)
        path.parent.mkdir(parents=True, exist_ok=True)
        with open(path, "wb") as f:
            shutil.copyfileobj(stream, f, length=1024 * 1024)   # 1 MB chunks, constant memory
        return self.url_for(key)

    def get_path(self, key): 
        p = self._p(key)
        return str(p) if p.exists() else None

    def url_for(self, key): return f"{self.url_prefix}/{key}"
    def exists(self, key):  return self._p(key).exists()
    def delete(self, key):  self._p(key).unlink(missing_ok=True)

    def delete_prefix(self, prefix):
        d = self._p(prefix)
        if not d.is_dir(): return 0
        n = sum(1 for _ in d.rglob("*") if _.is_file())
        shutil.rmtree(d, ignore_errors=True)
        return n

    def total_bytes(self, prefix=""):
        d = self._p(prefix) if prefix else self.root
        return sum(f.stat().st_size for f in d.rglob("*") if f.is_file()) if d.is_dir() else 0
```

Expose a single instance in [`config.py`](../../backend/app/config.py):

```python
STORAGE: StorageBackend = LocalDiskBackend(root=UPLOADS_DIR, url_prefix="/uploads")
```

> The `_p()` traversal guard is not optional. Keys are built from client-supplied `photo_id` and filenames; without it, a crafted `photo_id` of `../../etc/x` writes outside the uploads root.

**Key scheme** — one convention everywhere:

```
thumbnails/{session_id}/{photo_id}.jpg
originals/{session_id}/{photo_id}.{ext}
exports/{session_id}/{variation_id}.pdf
```

Deleting a session becomes `STORAGE.delete_prefix(f"originals/{session_id}")` — one call per asset type.

| Site | Was | Becomes |
|---|---|---|
| [`main.py:176`](../../backend/app/main.py) ingest thumbnails | `open(target_path, "wb")` | `STORAGE.put_stream(f"thumbnails/{sid}/{pid}.jpg", f.file)` |

### Task 3 — Stream instead of buffer

`UploadFile.file` is a `SpooledTemporaryFile`; `shutil.copyfileobj` streams it in fixed chunks. Enforce the size cap *during* the copy rather than after, so an oversized upload is rejected before it lands:

```python
async def _stream_capped(upload: UploadFile, key: str, cap: int) -> str:
    total = 0
    def _guarded():
        nonlocal total
        while chunk := upload.file.read(1024 * 1024):
            total += len(chunk)
            if total > cap:
                raise HTTPException(413, f"File exceeds {cap // (1024*1024)}MB limit.")
            yield chunk
    return STORAGE.put_stream_iter(key, _guarded())
```

Add `put_stream_iter(key, iterator)` to the interface alongside `put_stream`.

### Task 4 — Demand-driven original upload

Today `streamOriginalsInBackground(origMap)` ([`App.jsx:70`](../../frontend/src/App.jsx)) is called with *every* photo. Restrict and prioritise it:

1. **Survivors only.** Ingest already returns the survivor list per chunk. Filter `origMap` down to those IDs before queueing — typically a 40% reduction for free.
2. **Placement order.** Once a job completes, the chosen variation names exactly which photos appear in spreads. Re-prioritise the queue so those upload first:

```js
const prioritiseQueue = (queue, variation) => {
  const placed = new Set(
    variation.spreads.flatMap(s =>
      [...s.left_page.slots, ...s.right_page.slots]
        .filter(sl => sl.photo_id).map(sl => sl.photo_id)
    )
  );
  return [...queue].sort((a, b) => (placed.has(b) ? 1 : 0) - (placed.has(a) ? 1 : 0));
};
```

3. **Export gate.** `/api/export-pdf` must verify every placed photo has `original_synced = True` and return `409` with the outstanding list rather than silently exporting a placeholder:

```python
missing = [pid for pid in placed_ids if not SessionStore.get_photo(pid).original_synced]
if missing:
    raise HTTPException(409, {
        "error": "originals_pending",
        "pending_count": len(missing),
        "message": f"{len(missing)} high-resolution photos are still uploading.",
    })
```

The frontend shows "Preparing print files — 47 of 250" and retries. This is the honest version of the behaviour that currently produces a placeholder PDF.

### Task 5 — Disk guard

In [`config.py`](../../backend/app/config.py):

```python
MAX_BYTES_PER_SESSION = int(os.environ.get("MAX_BYTES_PER_SESSION", 3 * 1024**3))    # 3 GB
GLOBAL_DISK_WATERMARK  = int(os.environ.get("GLOBAL_DISK_WATERMARK", 60 * 1024**3))  # 60 GB
```

Check the global watermark in `POST /api/sessions` (reject with `503 {"error": "at_capacity"}`), and the per-session cap in `/api/upload-originals` (reject with `413`). Track running totals on the `sessions.total_bytes` column added in 1.1 — `total_bytes()` walks the filesystem and is too slow to call per request.

> A demo that dies from a full disk is worse than one that says "at capacity."

### Task 6 — Evict IndexedDB promptly

[`App.jsx:87`](../../frontend/src/App.jsx) saves the blob to IndexedDB, uploads, then removes on success. That is correct. Two fixes:

- **Don't save non-survivors at all** — currently every photo is persisted, including ones the filter rejected.
- **Add a startup sweep** dropping records older than 24 h, so an abandoned session doesn't leave gigabytes in the user's browser forever.

## 6. Test plan

**Unit**
- `LocalDiskBackend` round-trips put → exists → get_path → delete.
- `delete_prefix("originals/sess_x")` removes only that session's files.
- `_p("../../etc/passwd")` raises `ValueError`.
- Streaming a 25 MB file against a 20 MB cap raises `413` **and leaves no partial file**.

**Integration**
- Ingest 100 photos: `/uploads/originals/` stays empty until the background sync runs.
- Export with 5 originals outstanding → `409` with `pending_count: 5`, not a placeholder PDF.
- Session exceeding `MAX_BYTES_PER_SESSION` → `413`.
- Global watermark exceeded → `POST /api/sessions` returns `503`.

**Manual**
- 1,000-photo session; confirm peak disk stays under ~3 GB.

## 7. Exit criteria

- [ ] Ingest requests <5 MB regardless of photo count.
- [ ] `grep -n "originals" frontend/src/utils/client_downsampler.js` returns nothing.
- [ ] A 1,000-photo session consumes <3 GB of disk.
- [ ] Each original crosses the network exactly **once**.
- [ ] All file I/O goes through `STORAGE`; no `open(UPLOADS_*` remains in `main.py`.
- [ ] Export blocks with a clear `409` when originals are pending.
- [ ] No original is buffered whole in memory.

## 8. Risks & rollback

| Risk | Mitigation |
|---|---|
| Export blocked because a background upload stalled | Prioritised queue means placed photos upload first; the `409` reports exactly what's outstanding and the client retries. Strictly better than today's silent placeholder. |
| Storage abstraction is over-engineering for a local demo | ~1 day now with 4 call sites; considerably more once originals are referenced across export, preview and retention. S3 is the stated end state. |
| Path-scheme change orphans existing files | Dev-only data. Clear `backend/app/uploads/` — it should stop being git-tracked regardless. |
| Prioritisation adds client complexity | It is one `sort` over an array of IDs. Ship the survivors-only filter first (most of the win), prioritisation second. |

**Rollback:** `STORAGE` is a drop-in for direct path use, so reverting means restoring the direct `open()` calls. The ingest-originals deletion is the only non-additive change; keeping the frontend from sending them makes the backend block dead either way.
