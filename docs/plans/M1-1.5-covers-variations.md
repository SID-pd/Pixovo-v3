# Stage 1.5 — Covers & distinct variations

**Milestone 1 · 3–4 days · Depends on [1.2](M1-1.2-data-contract.md)**

---

## 1. Objective

Make the three themes read as three genuinely different books, each with a real, well-chosen cover. This is the defect reported directly: *"only the main cover is being shown, and that too is just a dummy."*

**Do not start until [Stage 1.2](M1-1.2-data-contract.md) is green.** Hero-based selection is unimplementable while `hero_score` is 0 for every photo.

## 2. Current state

Four compounding causes.

### Cause 1 — One cover photo, chosen by upload order

[`solver.py:79`](../../backend/app/engine/solver.py), inside the `for var_idx in range(3)` loop:

```python
cover_img = photos[0].url if photos else "/uploads/sample_placeholder.jpg"
```

`photos[0]` — the first photo in the array, for **all three variations**. `hero_score`, `layout_role` and `is_event_cover_hero` are never consulted, even though the filter engine computes an explicit `event_cover_photo_id` per cluster ([`filter_engine.py:845`](../../backend/app/engine/filter/filter_engine.py)).

### Cause 2 — The schema cannot express a multi-photo cover

[`schemas/photobook.py`](../../backend/app/schemas/photobook.py):

```python
class PhotobookVariation(BaseModel):
    cover_image_url: str          # ← a single URL
```

No amount of frontend work fixes a 4-photo collage against a one-URL contract.

### Cause 3 — The frontend tiles that one photo

[`BookCarousel3D.jsx`](../../frontend/src/components/BookCarousel3D.jsx):

```jsx
{/* COVER STYLE 3: 4-PHOTO GLASS COLLAGE */}
<div className="collage-2x2">
  <img src={item.cover_image_url} alt="c1" />
  <img src={item.cover_image_url} alt="c2" />
  <img src={item.cover_image_url} alt="c3" />
  <img src={item.cover_image_url} alt="c4" />
</div>
```

The same photo four times. Style 1 renders it twice (top and bottom halves). This is exactly why the covers look broken.

### Cause 4 — The sample fallback

When photo resolution fails, `photos[0]` is `sample_1` — a placeholder generated by `ensure_sample_placeholders()` ([`config.py:47`](../../backend/app/config.py)). Removed in [Stage 1.6](M1-1.6-fail-honestly.md).

### Also: are the three variations actually different?

Layout family does vary — [`solver.py:50`](../../backend/app/engine/solver.py):

```python
family_variant = LAYOUT_FAMILIES[(var_idx + variant_seed_offset) % len(LAYOUT_FAMILIES)]
```

with `LAYOUT_FAMILIES = ["BALANCED", "DOMINANT", "ALTERNATING"]` ([`dsa_solver.py:21`](../../backend/app/engine/dsa_solver.py)). But all three variations receive **the same photo order and the same chapter partition**, so spreads contain the same photos in the same sequence — only slot geometry shifts. Combined with an identical cover, the three read as one book in three palettes. Task 5 addresses this.

---

## 3. Target state

- `PhotobookVariation` carries a list of cover photos.
- Each cover style declares how many it needs (1, 2, or 4) and receives that many **distinct** photos.
- Covers are chosen by `hero_score`, with **no photo reused across variations**.
- Cover images resolve to 512px thumbnails, never originals.
- The three variations differ in photo ordering and emphasis, not only palette.
- A golden test locks the behaviour — the engine is fully deterministic (no `random` anywhere), so this is exactly assertable.

### Task 2 — Hero-aware, non-overlapping cover selection

New module `backend/app/engine/cover_selector.py`:

```python
from typing import List
from app.schemas.photobook import PhotoMeta, CoverPhoto

COVER_STYLES = [
    {"name": "SPLIT_BANNER", "photo_count": 2, "prefers": "LANDSCAPE"},
    {"name": "HERO_BAND",    "photo_count": 1, "prefers": "LANDSCAPE"},
    {"name": "COLLAGE_2X2",  "photo_count": 4, "prefers": "ANY"},
]

def _fits(photo: PhotoMeta, prefers: str) -> float:
    """Aspect-ratio affinity bonus, 0-15 points."""
    if prefers == "ANY":
        return 8.0
    if prefers == "LANDSCAPE":
        return 15.0 if photo.aspect_ratio >= 1.35 else (5.0 if photo.aspect_ratio >= 1.0 else 0.0)
    return 15.0 if photo.aspect_ratio <= 0.8 else (5.0 if photo.aspect_ratio <= 1.0 else 0.0)

def select_covers(photos: List[PhotoMeta], variation_count: int = 3) -> List[dict]:
    """
    Pick a distinct cover set per variation, best-hero-first, no photo reused.

    Deterministic: ties break on photo_id, so the same input always yields
    the same covers. Required by the golden test.
    """
    ranked = sorted(
        photos,
        key=lambda p: (-(p.hero_score or 0.0), -(p.face_count or 0), p.id),
    )
    used: set[str] = set()
    out = []

    for var_idx in range(variation_count):
        style = COVER_STYLES[var_idx % len(COVER_STYLES)]
        need = style["photo_count"]

        candidates = sorted(
            (p for p in ranked if p.id not in used),
            key=lambda p: (-((p.hero_score or 0.0) + _fits(p, style["prefers"])), p.id),
        )

        chosen = candidates[:need]
        # Degrade gracefully rather than fail when the pool is nearly exhausted
        if len(chosen) < need:
            filler = [p for p in ranked if p not in chosen]
            chosen += filler[: need - len(chosen)]

        used.update(p.id for p in chosen)
        out.append({
            "cover_style": style["name"],
            "cover_photos": [
                CoverPhoto(
                    photo_id=p.id,
                    url=p.thumbnail_url or p.url,     # thumbnail, never original
                    aspect_ratio=p.aspect_ratio,
                    hero_score=p.hero_score or 0.0,
                )
                for p in chosen
            ],
        })
    return out
```

**Why exclusion matters:** without `used`, all three variations pick the same top-ranked hero and you are back to one cover in three palettes. Exclusion is what makes them read as different books.

**Edge case — small sets.** Three variations need 2 + 1 + 4 = **7 distinct photos**. Below that the filler path reuses photos; log a warning and let it degrade rather than fail.

### Task 5 — Make the variations genuinely differ

Same photos in the same order across all three variations means three near-identical books. Give each variation a different **emphasis** while keeping chapter boundaries intact — the chronological story must survive:

```python
VARIATION_STRATEGIES = [
    {"name": "CHRONOLOGICAL", "chunk_size": 3, "hero_bias": 0.0},   # story order, even spreads
    {"name": "HERO_FORWARD",  "chunk_size": 2, "hero_bias": 1.0},   # best photos larger, tighter spreads
    {"name": "EXPANSIVE",     "chunk_size": 4, "hero_bias": 0.5},   # denser collages, more per spread
]
```

Apply `chunk_size` at the existing `cluster_photos_2tier_engine(ch_photos, chunk_size=...)` call ([`solver.py:57`](../../backend/app/engine/solver.py)), which currently hardcodes `2 if len(ch_photos) <= 4 else 3` for every variation. Use `hero_bias` to influence which photo becomes dominant within a spread.

This is deliberately conservative: it changes **pacing and emphasis**, not chapter order. Reordering chapters would break the narrative that [Stage 1.2](M1-1.2-data-contract.md) just restored.

### Task 6 — Golden test

The engine contains no `random` — verified across all of `app/engine/`. Output is a pure function of (photos, prompt, seed), which makes exact assertions possible:

```python
def test_covers_are_distinct_and_hero_ranked(fixture_photos_60):
    ai = generate_story_theme_batch("Family trip", len(fixture_photos_60))
    variations = generate_photobook_variations_engine(fixture_photos_60, ai)

    assert len(variations) == 3

    ids = [p.photo_id for v in variations for p in v.cover_photos]
    assert len(ids) == len(set(ids)), "A photo appears on more than one cover"
    assert not any(i.startswith("sample_") for i in ids), "Placeholder on a cover"

    expected = {"SPLIT_BANNER": 2, "HERO_BAND": 1, "COLLAGE_2X2": 4}
    for v in variations:
        assert len(v.cover_photos) == expected[v.cover_style]
        assert all("/thumbnails/" in p.url for p in v.cover_photos)

    # Top cover photo must be the highest-hero photo available
    best = max(fixture_photos_60, key=lambda p: p.hero_score)
    assert variations[0].cover_photos[0].photo_id == best.id

def test_variations_differ_beyond_palette(fixture_photos_60):
    v = generate_photobook_variations_engine(fixture_photos_60, ai_batch)
    sigs = [tuple(len(s.left_page.slots) + len(s.right_page.slots) for s in var.spreads) for var in v]
    assert len(set(sigs)) > 1, "All three variations have identical spread structure"

def test_output_is_deterministic(fixture_photos_60):
    a = generate_photobook_variations_engine(fixture_photos_60, ai_batch)
    b = generate_photobook_variations_engine(fixture_photos_60, ai_batch)
    assert a.model_dump() == b.model_dump()
```

## 8. Risks & rollback

| Risk | Mitigation |
|---|---|
| `hero_score` still 0 → selection degenerates to `ranked[0..n]` | Stage 1.2 is a hard prerequisite. Assert `max(hero_score) > 0` at the top of `select_covers` and log loudly if not. |
| Exclusion pushes weak photos onto variation 3's collage | Expected: 4 photos from a ranked list means covers 4–7. Acceptable, and better than one photo tiled. If it looks bad, allow limited reuse across variations while keeping *within*-cover distinctness. |
| Frontend/backend deploy skew | `cover_image_url` stays populated for one release; `CoverArt` falls back to it when `cover_photos` is empty. |
| Per-variation strategies produce an ugly layout | `chunk_size` is already a supported parameter of `cluster_photos_2tier_engine`; only the value changes. Tune against the fixture corpus. |
| Aspect-ratio scoring is guesswork | It is — `_fits()` weights are a starting point. Tune visually; the constants are isolated in one function. |

**Rollback:** schema fields are additive with defaults. Reverting means restoring `cover_img = photos[0].url` and the `idx % 3` frontend switch — two hunks, no data migration.
