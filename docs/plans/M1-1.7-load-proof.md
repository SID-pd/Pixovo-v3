# Stage 1.7 — Prove the load target

**Milestone 1 · 3–4 days · Depends on 1.1–1.6**

---

## 1. Objective

Demonstrate, repeatably and with numbers, that one machine serves **20 concurrent users × 1,000 photos each** through the full pipeline. Nothing in Stages 1.1–1.6 is real until measured. This stage also produces the capacity figure you can quote — a measured number is a far better asset than a claim.

---

## 2. Current state

No test infrastructure exists. `backend/tests/` contains only `__pycache__`. `pytest>=8.0.0` is in `requirements.txt` and has never run. The frontend has no test tooling in `package.json` at all.

There is no way today to know whether any change helps or hurts.

---

## 3. Target state

- A synthetic 1,000-photo corpus generated on demand — **never real user photos**.
- A load harness simulating 20 concurrent users end to end.
- Measurements for: time to first cover, time to complete album, peak RSS, peak disk, event-loop lag, filter throughput.
- Regression tests on the paths that have already broken once.
- A written capacity number for the demo machine.

### Task 2 — Synthetic corpus generator

`backend/tests/fixtures/generate_corpus.py`:

```python
"""
Deterministic synthetic photo corpus. Never uses real user photos.
Seeded so every run produces byte-identical images.
"""
import numpy as np, cv2, random
from pathlib import Path

def generate_corpus(out_dir: Path, count: int = 1000, seed: int = 42) -> list[dict]:
    rng = random.Random(seed)
    np.random.seed(seed)
    out_dir.mkdir(parents=True, exist_ok=True)
    manifest = []

    # Three temporal clusters with 2-hour gaps → must yield 3 chapters (Stage 1.2 assertion)
    base_ts = 1_700_000_000
    cluster_starts = [base_ts, base_ts + 7200, base_ts + 14400]

    for i in range(count):
        kind = _pick_kind(rng, i)          # sharp | blurry | dark | blown | junk_qr | burst_dup
        w, h = rng.choice([(4000, 3000), (3000, 4000), (4000, 4000)])
        img = _render(kind, w, h, rng)

        ts = cluster_starts[i % 3] + (i // 3) * 30
        path = out_dir / f"photo_{i:04d}_{kind}.jpg"
        cv2.imwrite(str(path), img, [cv2.IMWRITE_JPEG_QUALITY, 92])
        manifest.append({"path": str(path), "kind": kind, "timestamp_epoch": ts,
                         "expected_survives": kind in ("sharp", "dark")})
    return manifest
```

Composition — the mix decides what the filter engine is actually exercised on:

| Kind | Share | Purpose | Expected |
|---|---|---|---|
| `sharp` | 60% | Normal photos, faces, varied composition | survives |
| `burst_dup` | 15% | Near-identical consecutive frames | 1 of N survives |
| `blurry` | 10% | Gaussian-blurred | rejected |
| `dark` / `blown` | 8% | Exposure extremes incl. artistic low-key | mixed |
| `junk_qr` | 5% | QR codes, receipts, screenshots | rejected |
| `corrupt` | 2% | Truncated files | rejected gracefully |

> Include a few *artistic* low-key frames that must **survive**. The exposure guard is explicitly built to protect them, and a corpus of only extremes cannot detect a regression that starts rejecting them.

### Task 3 — Load harness

`backend/tests/load/run_load_test.py`:

```python
"""
20 concurrent users × 1000 photos, full pipeline.
Usage: python -m tests.load.run_load_test --users 20 --photos 1000
"""
import asyncio, time, httpx, psutil, statistics, json

async def simulate_user(client, user_idx, corpus, photos_per_user):
    t = {"user": user_idx}
    t0 = time.perf_counter()

    r = await client.post("/api/sessions", json={"expected_photo_count": photos_per_user})
    session_id = r.json()["session_id"]

    # Chunked thumbnail ingest, sequential per user (mirrors the real client)
    for ci, chunk in enumerate(chunks(corpus[:photos_per_user], 40)):
        files = [("thumbnails", (f"{p['photo_id']}_thumb.jpg", p["thumb_bytes"], "image/jpeg"))
                 for p in chunk]
        await client.post("/api/photobook/ingest", files=files, data={
            "session_id": session_id, "chunk_index": ci,
            "metadata_json": json.dumps([p["meta"] for p in chunk]),
        })
    t["ingest_s"] = time.perf_counter() - t0

    r = await client.post("/api/generate-async",
                          json={"session_id": session_id, "user_prompt": "Family trip"})
    job_id = r.json()["job_id"]

    while True:
        job = (await client.get(f"/api/jobs/{job_id}")).json()
        if job["status"] == "completed":
            t["first_cover_s"] = time.perf_counter() - t0
            break
        if job["status"] == "failed":
            t["error"] = job["message"]
            return t
        await asyncio.sleep(0.5)

    t["total_s"] = time.perf_counter() - t0
    return t

async def sample_health(client, stop, out):
    """Event-loop responsiveness — the single most diagnostic metric."""
    while not stop.is_set():
        t0 = time.perf_counter()
        try:
            await client.get("/health", timeout=5.0)
            out.append(time.perf_counter() - t0)
        except Exception:
            out.append(5.0)
        await asyncio.sleep(0.25)
```

### Task 5 — Admission control

Twenty concurrent 1,000-photo sessions will likely exceed what one machine handles gracefully. That is fine — **queue honestly** rather than degrade silently:

```python
ACTIVE_SESSIONS = set()
MAX_ACTIVE = int(os.environ.get("PIXOVO_MAX_ACTIVE_SESSIONS", 20))

@app.post("/api/sessions", status_code=201)
async def create_session(req: CreateSessionRequest):
    if len(ACTIVE_SESSIONS) >= MAX_ACTIVE:
        raise HTTPException(503, {
            "error": "at_capacity",
            "queue_position": len(ACTIVE_SESSIONS) - MAX_ACTIVE + 1,
            "retry_after_seconds": 30,
            "message": "We're at capacity. Your place is held.",
        })
```

Set `MAX_ACTIVE` from the measurement, not a guess. The frontend renders queue position ([Stage 2.4](M2-2.4-interaction-polish.md)).

def test_slots_never_overlap(n, fixture_photos):

### Task 7 — Memory and disk soak

```python
def test_rss_flat_across_sessions():
    """Three consecutive 1000-photo sessions must not grow RSS monotonically."""
    readings = []
    for _ in range(3):
        run_full_session(1000)
        gc.collect()
        readings.append(psutil.Process().memory_info().rss)
    growth = (readings[-1] - readings[0]) / readings[0]
    assert growth < 0.15, f"RSS grew {growth:.0%} across 3 sessions — leak suspected"
```

This is what catches the unbounded-cache class of bug that [Stage 1.4](M1-1.4-server-unblock.md) Task 5 addresses. Also assert disk is reclaimed after session deletion via `STORAGE.delete_prefix()`.

## 6. Exit criteria

- [ ] 20 concurrent × 1,000 photos completes with **0 failed sessions**.
- [ ] p99 `/health` latency < 200 ms throughout.
- [ ] Peak RSS below a stated ceiling; RSS growth < 15% across 3 sessions.
- [ ] Peak disk < 60 GB; reclaimed after session deletion.
- [ ] Threads-vs-processes decided by measurement, recorded.
- [ ] `MAX_ACTIVE_SESSIONS` set from data, not guessed.
- [ ] All regression tests green; CI passing on a PR.
- [ ] `docs/CAPACITY.md` written with real numbers and the hardware they came from.
- [ ] The load test passes **three consecutive times** — flaky is not passing.

## 7. Risks & rollback

| Risk | Mitigation |
|---|---|
| One machine cannot do 20 × 1,000 | Entirely possible, and finding out is the point. Admission control degrades honestly; the measured number tells you what hardware the demo needs. Report it plainly rather than tuning until the test passes. |
| The harness itself is the bottleneck | Run it from a separate process; measure client-side CPU. If the client saturates, split across machines or reduce to 10 users × 2 rounds. |
| Corpus generation is slow | Generate once, cache in a gitignored dir keyed by seed+count. |
| Synthetic photos don't exercise real filter paths | Deliberate composition (Task 2) covers each gate. Validate once against a small real set held **outside** the repo, then never commit it. |
| Load test destabilises CI | Manual/nightly only. CI runs unit + integration on a 60-photo corpus. |
