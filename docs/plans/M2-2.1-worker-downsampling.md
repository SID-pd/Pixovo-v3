# Stage 2.1 — Worker-based downsampling

**Milestone 2 · 2–3 days · Depends on [1.1](M1-1.1-session-continuity.md)**

---

## 1. Objective

Move image downsampling off the main thread. This is the single largest perceived-performance defect: a 150-photo batch visibly locks the UI, and 1,000 photos is an unusable freeze. It is also where client-side EXIF extraction belongs, which [Stage 1.2](M1-1.2-data-contract.md) needs for real capture times and GPS.

---

## 2. Current state

### 2.1 Everything runs on the main thread

[`client_downsampler.js:56`](../../frontend/src/utils/client_downsampler.js):

```js
const canvas = document.createElement('canvas');   // ← DOM canvas, main thread only
const ctx = canvas.getContext('2d');
ctx.drawImage(img, 0, 0, width, height);
canvas.toBlob(callback, 'image/jpeg', this.quality);
```

`processBatch` ([:116](../../frontend/src/utils/client_downsampler.js)) runs 4 of these "concurrently", but `Promise.all` over main-thread work is interleaving, not parallelism — every `drawImage` and `toBlob` still executes on the one thread that also paints the UI. Nothing else can run during it.

`ARCHITECTURE.md` Stage 1 claims "512px WebP + EXIF parsing in browser Web Workers". None of the three claims is true: main thread, JPEG output, no EXIF parsing.

### 2.2 Object URLs leak

[`PhotoUploader.jsx:52`](../../frontend/src/components/PhotoUploader.jsx):

```js
const previewItems = processedResults.map(p => ({
  previewUrl: URL.createObjectURL(p.thumbnail_blob),   // never revoked
  ...
}));
```

One object URL per photo, never released. At 1,000 photos that is 1,000 retained blobs — the browser cannot free the underlying memory while a URL references it.

### 2.3 The preview grid renders every photo

[`PhotoUploader.jsx:212`](../../frontend/src/components/PhotoUploader.jsx) maps `localPhotos` to `<img>` elements inside a `maxHeight: 320px, overflowY: auto` container. At 1,000 photos that is 1,000 image elements decoded and laid out, of which ~12 are visible.

### 2.4 A new downsampler per render

[`PhotoUploader.jsx:19`](../../frontend/src/components/PhotoUploader.jsx) constructs `new PixovoClientDownsampler({...})` in the component body — a fresh instance on every render. Harmless today, but it becomes a bug the moment the instance owns a worker pool.

---

## 3. Target state

- Downsampling runs in a Web Worker pool sized to `navigator.hardwareConcurrency` (clamped to 1 on low-end $\le 2$ GB devices per [FAILSAFE_AND_FALLBACK_SPEC.md](../FAILSAFE_AND_FALLBACK_SPEC.md)).
- The main thread stays responsive; no task blocks it longer than ~50 ms.
- EXIF `DateTimeOriginal` and GPS are extracted from the **original** file before downsampling.
- Object URLs are revoked; the preview grid is virtualized.
- Memory leaks & crash fallbacks (circuit breaker, HEIC/RAW server bypass, watchdog timeout) adhere to [FAILSAFE_AND_FALLBACK_SPEC.md](../FAILSAFE_AND_FALLBACK_SPEC.md).

## 4. Tasks

### Task 1 — The worker

`frontend/src/workers/downsample.worker.js`:

```js
/**
 * Downsample worker. Receives a File, returns a thumbnail blob + metadata.
 * Uses OffscreenCanvas + createImageBitmap — no DOM, no main thread.
 */

self.onmessage = async (e) => {
  const { photoId, file, maxDimension, quality } = e.data;
  try {
    const exif = await parseExif(file);          // read BEFORE decode; canvas drops EXIF
    const bitmap = await createImageBitmap(file);

    let { width, height } = bitmap;
    const nativeAspect = width / Math.max(1, height);
    if (width > height) {
      if (width > maxDimension) { height = Math.round(height * maxDimension / width); width = maxDimension; }
    } else {
      if (height > maxDimension) { width = Math.round(width * maxDimension / height); height = maxDimension; }
    }

    const canvas = new OffscreenCanvas(width, height);
    const ctx = canvas.getContext('2d');
    ctx.imageSmoothingEnabled = true;
    ctx.imageSmoothingQuality = 'high';
    ctx.drawImage(bitmap, 0, 0, width, height);
    const blob = await canvas.convertToBlob({ type: 'image/jpeg', quality });

    const result = {
      photoId,
      thumbnail_blob: blob,
      thumbnail_size_bytes: blob.size,
      original_width: bitmap.width,
      original_height: bitmap.height,
      aspect_ratio: parseFloat(nativeAspect.toFixed(4)),
      orientation: nativeAspect >= 1.2 ? 'LANDSCAPE' : (nativeAspect <= 0.8 ? 'PORTRAIT' : 'SQUARE'),
      timestamp_epoch: exif.timestamp_epoch || Math.floor(file.lastModified / 1000),
      timestamp_source: exif.timestamp_epoch ? 'exif' : 'file_mtime',
      latitude: exif.latitude ?? null,
      longitude: exif.longitude ?? null,
    };

    bitmap.close();                               // release decoded pixels immediately
    self.postMessage({ ok: true, result }, [await blob.arrayBuffer()]);
  } catch (err) {
    self.postMessage({ ok: false, photoId, error: err.message });
  }
};
```

> `bitmap.close()` is important. An `ImageBitmap` of a 4000×3000 photo holds ~48 MB of decoded RGBA. Without an explicit close, four in-flight bitmaps is ~200 MB waiting on GC.

### Task 2 — Minimal EXIF reader

`frontend/src/workers/exif.js` — no dependency; read only the fields that matter:

```js
/**
 * Minimal EXIF reader: DateTimeOriginal + GPS from a JPEG APP1 segment.
 * Reads only the first 128KB — EXIF lives at the head of the file.
 */
export async function parseExif(file) {
  const head = await file.slice(0, 131072).arrayBuffer();
  const view = new DataView(head);
  if (view.getUint16(0) !== 0xFFD8) return {};        // not a JPEG

  let offset = 2;
  while (offset < view.byteLength - 4) {
    const marker = view.getUint16(offset);
    const size = view.getUint16(offset + 2);
    if (marker === 0xFFE1) return parseTiff(view, offset + 10);   // APP1, skip "Exif\0\0"
    if ((marker & 0xFF00) !== 0xFF00) break;
    offset += 2 + size;
  }
  return {};
}
```

`parseTiff` walks IFD0 for tag `0x9003` (`DateTimeOriginal`, format `"YYYY:MM:DD HH:MM:SS"`) and the GPS IFD (`0x8825`) for tags `0x0001`–`0x0004`. Roughly 80 lines. Honour the endianness marker (`0x4949` little / `0x4D4D` big) — getting this wrong yields plausible garbage rather than an obvious failure.

**This is the only way to get true capture time and GPS.** The canvas re-encode strips all metadata, so without it [Stage 1.2](M1-1.2-data-contract.md)'s chaptering falls back to file mtime and the 5-km GPS rule can never fire.

### Task 3 — Worker pool

`frontend/src/utils/worker_pool.js`:

```js
export class WorkerPool {
  constructor(workerFactory, size = Math.min(4, navigator.hardwareConcurrency || 2)) {
    this.workers = Array.from({ length: size }, () => ({ worker: workerFactory(), busy: false }));
    this.queue = [];
  }

  run(payload, transfer = []) {
    return new Promise((resolve, reject) => {
      this.queue.push({ payload, transfer, resolve, reject });
      this._pump();
    });
  }

  _pump() {
    const slot = this.workers.find(w => !w.busy);
    if (!slot || this.queue.length === 0) return;
    const task = this.queue.shift();
    slot.busy = true;
    const onDone = (e) => {
      slot.worker.removeEventListener('message', onDone);
      slot.busy = false;
      e.data.ok ? task.resolve(e.data.result) : task.reject(new Error(e.data.error));
      this._pump();
    };
    slot.worker.addEventListener('message', onDone);
    slot.worker.postMessage(task.payload, task.transfer);
  }

  terminate() { this.workers.forEach(w => w.worker.terminate()); this.queue = []; }
}
```

Cap at 4 regardless of `hardwareConcurrency`. Image decode is memory-bound, not CPU-bound; 16 workers each holding a decoded 4K bitmap is ~800 MB and will OOM a tab before it goes faster.

### Task 4 — Rewrite `processBatch`

```js
async processBatch(fileList, onProgress = null) {
  const files = Array.from(fileList).filter(f =>
    f.type.startsWith('image/') || /\.(jpe?g|png|webp|heic|tiff)$/i.test(f.name));

  if (!this.pool) {
    this.pool = new WorkerPool(() =>
      new Worker(new URL('../workers/downsample.worker.js', import.meta.url), { type: 'module' }));
  }

  let completed = 0;
  const results = await Promise.all(files.map(async (file) => {
    const photoId = this.generatePhotoId();
    try {
      const r = await this.pool.run({
        photoId, file, maxDimension: this.maxDimension, quality: this.quality,
      });
      return { ...r, photo_id: photoId, filename: file.name,
               original_file: file, original_size_bytes: file.size };
    } catch (err) {
      console.warn(`[Downsampler] Skipping ${file.name}:`, err);
      return null;
    } finally {
      onProgress?.(++completed, files.length);
    }
  }));

  return results.filter(Boolean);
}
```

`Promise.all` over the whole list is now correct — the pool bounds concurrency, and `File` objects are lazy disk references, so holding 1,000 of them costs almost nothing.

> `new URL(..., import.meta.url)` is the form Vite needs to bundle a worker. A bare string path silently 404s in production builds.

### Task 5 — Fix the leaks and the grid

**Revoke object URLs** in [`PhotoUploader.jsx`](../../frontend/src/components/PhotoUploader.jsx):

```js
useEffect(() => () => {
  localPhotos.forEach(p => p.previewUrl && URL.revokeObjectURL(p.previewUrl));
}, [localPhotos]);
```

**Only create URLs for what is shown.** Generate them lazily for the visible window rather than eagerly for all 1,000.

**Virtualize the grid.** The project already has a virtualization pattern in [`SpreadViewer.jsx`](../../frontend/src/components/SpreadViewer.jsx) (visible + 2 buffer) — reuse the approach rather than adding a dependency. Or cap the grid at the first 60 photos with a "+940 more" affordance, which is simpler and reads better at 1,000.

**Hoist the downsampler** out of the render body:

```js
const downsamplerRef = useRef(null);
if (!downsamplerRef.current) {
  downsamplerRef.current = new PixovoClientDownsampler({ maxDimension: 512, quality: 0.85 });
}
useEffect(() => () => downsamplerRef.current?.pool?.terminate(), []);
```

Terminating on unmount matters — orphaned workers keep running and holding memory.

### Task 6 — Fallback for older browsers

`OffscreenCanvas` in workers is unsupported in Safari < 16.4. Feature-detect once and fall back to the existing main-thread path:

```js
const SUPPORTS_WORKER_CANVAS =
  typeof Worker !== 'undefined' &&
  typeof OffscreenCanvas !== 'undefined' &&
  typeof createImageBitmap !== 'undefined';
```

Keep `processSinglePhoto()` as the fallback implementation. Log which path is taken so the load numbers are interpretable.

## 6. Test plan

**Unit**
- `parseExif` on a fixture JPEG with known `DateTimeOriginal` returns the right epoch.
- `parseExif` on a stripped JPEG returns `{}` — no throw.
- Both endiannesses parse correctly.
- `WorkerPool` with size 2 and 10 tasks: never more than 2 in flight, all 10 resolve.
- A worker error rejects only that task; the pool keeps serving.

**Performance — the point of the stage**
- Chrome Performance panel, 200-photo batch: **no long task > 50 ms** on the main thread.
- Frame rate stays ≥ 30 fps during a 1,000-photo downsample.
- Tab memory returns to baseline within 30 s of completion.

**Compatibility**
- Force `SUPPORTS_WORKER_CANVAS = false` → fallback path still produces correct thumbnails.

## 8. Risks & rollback

| Risk | Mitigation |
|---|---|
| Worker bundling breaks in production build | Test `npm run build` + `npm run preview`, not just `npm run dev`. Vite's dev server is more forgiving about worker resolution. |
| EXIF parser mishandles an exotic format | Wrap in try/catch, return `{}`, fall back to `file.lastModified`. Never let metadata parsing fail an upload. |
| HEIC files fail `createImageBitmap` | Already unsupported today. Detect and reject with a clear message rather than a silent skip. |
| Memory spike from parallel decodes | Cap the pool at 4; `bitmap.close()` immediately after draw. Measure with 4000×3000 inputs. |
| Transferables mishandled | Transferring the blob's ArrayBuffer neuters it in the worker — correct, since the worker is done with it. Verify the blob is intact on the main thread. |

**Rollback:** the main-thread path is retained as the fallback. Flipping `SUPPORTS_WORKER_CANVAS` to `false` restores the old behaviour without a code revert.
