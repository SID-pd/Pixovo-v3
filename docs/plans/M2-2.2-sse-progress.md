# Stage 2.2 — SSE progress

**Milestone 2 · 2 days · Depends on [1.1](M1-1.1-session-continuity.md), [1.7](M1-1.7-load-proof.md)**

---

## 1. Objective

Replace fixed-interval polling with server-sent events, and replace fake milestone progress with real per-photo progress. At the 20-user target, polling costs 40 requests/second of pure overhead against a server already at capacity — and it makes the progress bar jump in 500 ms steps between four hardcoded values.

## 2. Current state

### 2.3 Ingest has no progress channel at all

Filtering 1,000 photos is the longest phase, and the client learns nothing until each chunk's HTTP response returns. [Stage 1.1](M1-1.1-session-continuity.md) gives per-chunk granularity; per-photo needs a push channel.

## 3. Target state

- Progress reflects real work: photos filtered, spreads solved.

## 4. Tasks

### Task 1 — Progress bus

`backend/app/progress.py` — decoupled from HTTP so any layer can publish:

```python
import asyncio
from collections import defaultdict
from typing import AsyncIterator, Dict, Any

class ProgressBus:
    """In-process pub/sub for job progress. One queue per subscriber."""

    def __init__(self):
        self._subs: Dict[str, list[asyncio.Queue]] = defaultdict(list)
        self._last: Dict[str, dict] = {}          # replay for late/reconnecting subscribers

    def publish(self, job_id: str, event: Dict[str, Any]) -> None:
        self._last[job_id] = event
        for q in self._subs[job_id]:
            try:
                q.put_nowait(event)
            except asyncio.QueueFull:
                pass                              # slow consumer: drop, next event supersedes

    async def subscribe(self, job_id: str) -> AsyncIterator[dict]:
        q: asyncio.Queue = asyncio.Queue(maxsize=32)
        self._subs[job_id].append(q)
        try:
            if job_id in self._last:
                yield self._last[job_id]          # immediate state on connect
            while True:
                event = await q.get()
                yield event
                if event.get("status") in ("completed", "failed"):
                    return
        finally:
            self._subs[job_id].remove(q)
            if not self._subs[job_id]:
                self._subs.pop(job_id, None)
                self._last.pop(job_id, None)

progress_bus = ProgressBus()
```

Dropping on a full queue is deliberate: progress events are **state**, not a log. A subscriber that missed event 47 is fully corrected by event 48.

> `publish` is sync and called from pool threads via `loop.call_soon_threadsafe(...)`. `asyncio.Queue` is not thread-safe; publishing directly from a worker thread is a race.

### Task 2 — SSE endpoint

```python
from fastapi.responses import StreamingResponse
import json

@app.get("/api/jobs/{job_id}/stream")
async def stream_job_progress(job_id: str):
    job = JOBS_STORE.get(job_id) or SessionStore.get_job(job_id)
    if not job:
        raise HTTPException(404, "Job not found.")

    async def event_gen():
        try:
            async for event in progress_bus.subscribe(job_id):
                yield f"data: {json.dumps(event)}\n\n"
        except asyncio.CancelledError:
            logger.debug(f"[SSE] Client disconnected from {job_id}")
            raise

    return StreamingResponse(event_gen(), media_type="text/event-stream", headers={
        "Cache-Control": "no-cache",
        "Connection": "keep-alive",
        "X-Accel-Buffering": "no",       # disable nginx proxy buffering
    })
```

Keep `GET /api/jobs/{job_id}` as the fallback and the resume path. Add a keepalive comment every 15 s (`yield ": keepalive\n\n"`) so idle proxies don't close the connection.

**Connection budget:** SSE holds a connection open per job. 20 concurrent users is 20 connections — fine for uvicorn. Browsers cap ~6 connections per origin on HTTP/1.1, but that is per-client and each client holds one.

### Task 4 — Client hook

`frontend/src/hooks/useJobProgress.js`:

```js
import { useEffect, useRef, useState } from 'react';

export function useJobProgress(jobId, { onComplete, onError } = {}) {
  const [state, setState] = useState({ progress: 0, message: '', phase: 'queued', detail: null });
  const esRef = useRef(null);
  const pollRef = useRef(null);

  useEffect(() => {
    if (!jobId) return;
    let cancelled = false;

    const startPolling = () => {                       // fallback
      if (pollRef.current) return;
      pollRef.current = setInterval(async () => {
        try {
          const job = await (await fetch(`/api/jobs/${jobId}`)).json();
          if (cancelled) return;
          setState(s => ({ ...s, ...job }));
          if (job.status === 'completed') { cleanup(); onComplete?.(job); }
          if (job.status === 'failed')    { cleanup(); onError?.(job); }
        } catch { /* keep trying */ }
      }, 2000);
    };

    const cleanup = () => {
      esRef.current?.close();  esRef.current = null;
      clearInterval(pollRef.current); pollRef.current = null;
    };

    try {
      const es = new EventSource(`/api/jobs/${jobId}/stream`);
      esRef.current = es;
      es.onmessage = (e) => {
        if (cancelled) return;
        const data = JSON.parse(e.data);
        setState(data);
        if (data.status === 'completed') { cleanup(); onComplete?.(data); }
        if (data.status === 'failed')    { cleanup(); onError?.(data); }
      };
      es.onerror = () => { es.close(); esRef.current = null; startPolling(); };
    } catch {
      startPolling();
    }

    return () => { cancelled = true; cleanup(); };     // ← the cleanup today's code lacks
  }, [jobId]);

  return state;
}
```

`EventSource` reconnects automatically on transient failure; `onerror` fires only when it gives up, at which point polling takes over at a gentler 2 s.

Replace `pollJobStatus` in [`App.jsx`](../../frontend/src/App.jsx) with this hook. The `useEffect` return is the fix for the leaked interval.

## 6. Test plan

**Unit**
- `ProgressBus`: two subscribers both receive; a late subscriber gets the replayed last event; unsubscribing removes the queue.
- A full queue drops without raising.
- `publish` from a thread via `call_soon_threadsafe` arrives on the loop.

**Integration**
- SSE stream on a real job emits monotonically increasing progress ending at 100.
- Client disconnect mid-stream cleans up server-side (no queue leak in `_subs`).
- 404 for an unknown job.

**Client**

- Unmount closes the connection and clears the interval — assert no requests after unmount.

**Load**

## 8. Risks & rollback

| Risk | Mitigation |
|---|---|
| SSE blocked by a proxy | `X-Accel-Buffering: no` plus keepalives; automatic polling fallback means worst case is today's behaviour. |
| Progress bus leaks on abandoned jobs | `finally` removes the queue; last-event cache is cleared when the last subscriber leaves. Assert `_subs` is empty after tests. |
| Callback from executor thread races the loop | `loop.call_soon_threadsafe` for every cross-thread publish. Do not call `publish` directly from a pool thread. |
| Per-photo events flood the client | Throttled to every 5th photo and on completion — at most ~200 events for 1,000 photos. |
| `BackgroundTasks` job outlives the request | Already true today. SSE subscribes by `job_id`, independent of the originating request. |

**Rollback:** polling is retained as the fallback path. Removing the `EventSource` branch from the hook restores the old behaviour; the SSE endpoint can stay, unused.
