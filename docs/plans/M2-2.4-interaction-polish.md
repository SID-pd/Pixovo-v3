## 1. Objective

Close the remaining gaps between "works" and "feels finished": GPU-composited carousel motion, honest queue and error states, and removal of the blocking dialogs that can break a long upload. This is the last stage before Milestone 3.

## 2. Current state

### 2.1 Blocking `alert()` in the upload path

Three sites use modal `alert()`:

- [`App.jsx:168`](../../frontend/src/App.jsx) — `alert(\`Ingestion error: ${errDetail}\`)`
- [`App.jsx`](../../frontend/src/App.jsx) — `alert("Failed to submit job")`
- [`PhotoUploader.jsx:30`](../../frontend/src/components/PhotoUploader.jsx) — `alert("Please upload valid image files...")`

`alert()` **halts the JavaScript event loop until dismissed**. During a chunked 1,000-photo upload that pauses every in-flight fetch and the entire upload loop. A user who steps away mid-upload returns to a stalled session caused by the error dialog rather than the error.

### 2.2 Carousel animation is unspecified

[`BookCarousel3D.jsx`](../../frontend/src/components/BookCarousel3D.jsx) applies `.carousel-card` / `.carousel-card.hero` classes with the transition defined in [`storymode.css`](../../frontend/src/styles/storymode.css). Needs auditing: any transition touching `width`, `height`, `margin`, `top` or `left` forces layout on every frame. Only `transform` and `opacity` are composited.

### 2.3 No queue state

[Stage 1.7](M1-1.7-load-proof.md) adds admission control returning `503 {"error": "at_capacity", "queue_position": N}`. Nothing renders it — the user would see a generic failure at exactly the moment the system is working correctly under load.

### 2.4 No reduced-motion support

No `prefers-reduced-motion` handling anywhere. The 3D carousel and step transitions are exactly the kind of motion that triggers vestibular discomfort.

### 2.5 Reshuffle has no feedback

`onReshuffleVariations` sets `isReshuffling` and swaps the button label. The carousel itself doesn't indicate that new content is arriving — content changes under the user with no transition.

## 4. Tasks

### Task 1 — Toast system

`frontend/src/components/Toast.jsx` — a lightweight provider; no dependency needed:

```jsx
const ToastContext = createContext(null);

export function ToastProvider({ children }) {
  const [toasts, setToasts] = useState([]);

  const show = useCallback(({ title, message, tone = 'info', action, duration = 6000 }) => {
    const id = crypto.randomUUID();
    setToasts(t => [...t, { id, title, message, tone, action }]);
    if (duration) setTimeout(() => dismiss(id), duration);
    return id;
  }, []);

  const dismiss = useCallback((id) => setToasts(t => t.filter(x => x.id !== id)), []);

  return (
    <ToastContext.Provider value={{ show, dismiss }}>
      {children}
      <div className="toast-stack" role="status" aria-live="polite">
        {toasts.map(t => <Toast key={t.id} {...t} onDismiss={() => dismiss(t.id)} />)}
      </div>
    </ToastContext.Provider>
  );
}

export const useToast = () => useContext(ToastContext);
```

Tones: `info`, `success`, `warning`, `error`. Errors persist until dismissed (`duration: 0`); successes auto-dismiss.

`role="status"` + `aria-live="polite"` means screen readers announce toasts without interrupting — which is also the behaviour `alert()` gets wrong for everyone.

Replace all three `alert()` sites. Errors during upload become non-blocking, and the upload continues.

### Task 2 — Composited carousel motion

Audit [`storymode.css`](../../frontend/src/styles/storymode.css) for `.carousel-card`. Target shape:

```css
.carousel-card {
  transform: translate3d(0, 0, 0) scale(0.86);
  opacity: 0.55;
  transition: transform 320ms cubic-bezier(0.22, 1, 0.36, 1),
              opacity   320ms ease-out,
              border-color 200ms ease-out;
  backface-visibility: hidden;   /* avoids sub-pixel flicker mid-transform */
}

.carousel-card.hero {
  transform: translate3d(0, 0, 0) scale(1);
  opacity: 1;
  will-change: transform;        /* ONLY on the active card */
}

@media (prefers-reduced-motion: reduce) {
  .carousel-card,
  .carousel-card.hero { transition: none; }
}
```

Rules:
- **Only `transform` and `opacity`** transition. Anything touching geometry (`width`, `margin`, `left`) forces layout per frame.
- `will-change` **only on `.hero`**. Applying it to every card promotes every one to its own compositor layer and can exhaust GPU memory — the classic case where the optimisation is the regression.
- `translate3d` forces layer promotion for the transform itself.

Verify in the Performance panel: no "Layout" or "Recalculate Style" entries during the transition.

### Task 3 — Queue and capacity states

Handle `503 at_capacity` from `POST /api/sessions`:

```jsx
if (res.status === 503) {
  const { queue_position, retry_after_seconds } = await res.json();
  setCapacityState({ position: queue_position, retryIn: retry_after_seconds });
  // countdown, then retry automatically
}
```

Render as a calm, informative panel — not an error:

```
        Your album is next in line

  We're designing 20 albums right now.
  Yours starts in about 30 seconds.

        [ ●●●○○ position 3 ]
```

Auto-retry on the countdown. Never make the user click retry for a condition that resolves itself.

Handle `409 ingest_incomplete` from `/api/generate-async` ([Stage 1.6](M1-1.6-fail-honestly.md) Task 2) by disabling the generate button with a live count rather than surfacing an error:

```jsx
<button disabled={!sessionReady}>
  {sessionReady ? 'Create My Album' : `Preparing photos… ${received} of ${expected}`}
</button>
```

### Task 4 — Error states that name the fix

Every failure needs a cause and a next action:

| Condition | Title | Action |
|---|---|---|
| `NO_PHOTOS` | We couldn't find your photos | Upload again |
| `no_surviving_photos` | All photos were filtered out | Review what was rejected · Upload different photos |
| `originals_pending` | Print files still uploading | Auto-retry with count |
| `at_capacity` | Next in line | Auto-retry with countdown |
| Network failure | Connection lost | Retry (uploaded photos are safe) |

The `no_surviving_photos` case deserves care: it means the filter engine rejected everything. Show *why* — the ingest response already returns `rejected_photos` with reasons. "All 40 photos were rejected: 31 blurry, 9 duplicates" is actionable; "generation failed" is not.

### Task 5 — Reshuffle feedback

Cross-fade rather than swapping content under the user:

```jsx
<div className={`carousel-stage ${isReshuffling ? 'reshuffling' : ''}`}>
```

```css
.carousel-stage.reshuffling { opacity: 0.45; transition: opacity 160ms ease-out; }
.carousel-stage.reshuffling .carousel-card { pointer-events: none; }
```

Disable interaction during the swap so a click doesn't land on a card that is about to be replaced. Announce completion via a `success` toast: `Three new styles ready`.

### Task 6 — Keyboard and focus

The carousel is a set of clickable `<div>`s — unreachable by keyboard and invisible to assistive tech.

```jsx
<div role="radiogroup" aria-label="Album variations">
  {variations.map((item, idx) => (
    <div key={item.id}
         role="radio"
         aria-checked={idx === activeIdx}
         tabIndex={idx === activeIdx ? 0 : -1}
         onKeyDown={handleKey}
         onClick={() => setActiveIdx(idx)}>
```

Arrow keys move between variations, `Enter`/`Space` selects. A roving `tabIndex` (only the active card is tabbable) is the correct pattern for a radio group — it keeps the carousel one tab stop rather than three.

Add a visible focus ring; ensure it is not suppressed by a global `outline: none`.

### Task 7 — Final pass

- **Loading buttons**: every async action shows a spinner *inside* the button and disables it — prevents double-submit on `Create My Album` and `Export PDF`.
- **Empty states**: an explicit state for zero photos rather than an empty grid.
- **Export feedback**: PDF export is long-running; show a determinate bar (it becomes a job in [Milestone 3](../../ROADMAP.md)) and a clear "Download ready" affordance.
- **Tab title**: reflect progress (`Designing… 60% · Pixovo`) so a backgrounded tab still communicates.
- **Reduced motion**: single audit pass across all transitions.

## 8. Risks & rollback

| Risk | Mitigation |
|---|---|
| Toast provider requires wrapping the tree | Single change at the `App` root; `useToast` is a drop-in at call sites. |
| Removing `alert()` hides errors during development | Toasts are more visible, not less, and don't stop the event loop. Keep `console.error` alongside. |
| `will-change` overuse hurts performance | Active card only. Verify layer count in DevTools → Layers. |
| Keyboard nav conflicts with scroll handlers | Scope key handling to the focused carousel; do not attach at `document`. |
| Auto-retry hammers a saturated server | Honour `retry_after_seconds` from the server; add jitter; cap attempts and then offer manual retry. |

**Rollback:** every task is independent and cosmetic. Each can be reverted without touching another, and none affects backend contracts.
